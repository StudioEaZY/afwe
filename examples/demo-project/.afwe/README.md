# .afwe/ — Architecture-First Workspace Engine

This folder is a persistent, multi-level, two-way model of this codebase. It sits between
an LLM harness and the IDE. Humans and models both read it; the `afwe` engine keeps it in
sync with the code and tells you when they disagree.

| path | what it is | who writes it |
| --- | --- | --- |
| `afwe.yaml` | manifest, analyzer settings, confidence policy | humans / `afwe init` |
| `blueprint/blueprint.yaml` | the deterministic architecture tree + implementation mapping (files, symbols) | humans, LLMs, `afwe sync` (confident reconciliations only) |
| `blueprint/relations.yaml` | declared and inferred relationships between nodes | humans, LLMs, `afwe sync` |
| `blueprint/constraints.yaml` | structural rules that `afwe verify` enforces | humans, LLMs |
| `memory/<kind>/*.md` | knowledge: decisions, constraints, exceptions, terminology, problems — with scope metadata | humans, LLMs |
| `guardrails/passive/*.yaml` | micro-context injected when work touches their scope | humans, LLMs |
| `guardrails/active/*.yaml` | checks (commands, forbidden imports/patterns) that turn intent into errors | humans, LLMs |
| `workflows/*.yaml` | node-based workflows: intent → design → implementation, with provenance | humans, LLMs, studio |
| `abstractions/*.yaml` | custom lenses: a different grouping of the same nodes | humans, studio |
| `contracts/*.yaml` | what the harness must do when work crosses an AFWE boundary | humans |
| `index/` | derived retrieval index (regenerated by `afwe sync`) | engine |
| `state/` | derived: drift report, proposals, board, sync state | engine |
| `log/changes.jsonl` | append-only history of what changed, by whom, with confidence | engine |

Memory files = source of knowledge. Index = source of location. Code = source of implementation.
