# Engine architecture

```
                 ┌──────────────────────────────────────────────────────────────┐
  CLI ─────────▶ │  afwe_core::api::call(engine, op, params, origin)  (one JSON │
  MCP (stdio) ─▶ │  surface, ~60 ops, shared by every shell)                    │
  HTTP studio ─▶ │                                                              │
  Tauri ───────▶ │  ops.rs  (mutations)   context.rs  verify.rs  drift.rs  sync │
                 └───────┬───────────────────────┬──────────────────────────────┘
                         │                       │
                  store.rs (YAML/MD I/O)    engine.rs::Snapshot
                         │                       │  = sources + code model + mapping + index
                      .afwe/                analyze/ (tree-sitter)  mapping.rs  index.rs
```

## Crates

### `crates/afwe-core` (library)

| module | responsibility |
| --- | --- |
| `model.rs` | serde types for every file in `.afwe/` (manifest, blueprint, relations, constraints, memory, guardrails, workflows, lenses, contracts, board, findings, proposals, log) |
| `store.rs` | discovery of `.afwe/` (walks up from cwd), typed load/save of each file, memory front-matter parsing, fingerprint of the whole folder |
| `analyze/` | language-agnostic code model. `langs.rs` holds a `LangSpec` table (extensions → tree-sitter grammar + node-kind definitions); `mod.rs` walks the tree (respecting `.gitignore` and the manifest `ignore` globs), parses files, extracts symbols (kind, qualified name, structural AST path, blake3 fingerprint, exported?) and imports (resolved to files when relative), and falls back to regex import detection for languages without a grammar |
| `mapping.rs` | `NodeTable` (flattened tree, reference resolution by id/path/name, ancestors/descendants) and `Mapping` (file → node, deepest/most-specific wins; explicit symbol mappings) |
| `index.rs` | builds `index/*.json`: node ⇄ files ⇄ symbols ⇄ memory ⇄ guardrails, plus node-to-node code edges (counts of imports between differently-mapped files) |
| `engine.rs` | `Engine { store }` and `Snapshot` (all sources + code model + mapping + index, cached in `index/code.json` keyed by the code fingerprint so repeated calls are cheap) |
| `context.rs` | passive guardrail: for files / a symbol / a node, collect the node chain, memory whose scope matches, guardrails (with "exception applies here"), relations, constraints, code neighbourhood and the contract → `ContextBundle` (+ markdown rendering) |
| `verify.rs` | active guardrail: constraint violations from code edges, guardrail checks (`forbid_import`, `forbid_pattern`, `require_pattern`, `require_file`, `command`), optional drift summary; `VerifyReport { ok, errors, warnings, issues }` |
| `drift.rs` | `detect()` — findings with confidence and a proposed `Change`; heuristics for unmapped files (sibling agreement, import affinity, new-node proposal), missing files/symbols (rename detection by fingerprint / structural path), undeclared / unsupported relations, constraint violations, empty nodes, stale memory, broken references; `apply_change`, `resolve_proposal`, `review_impact` |
| `sync.rs` | analyse → index → detect → reconcile by policy (auto / soft+uncertain / proposal) → write `state/` + Board items + log → update `sync.json` fingerprints |
| `ops.rs` | every mutation (blueprint add/move/update/remove/map/relate/constrain, memory add/update/remove, guardrails, workflows incl. `promote`, lenses); each op validates references, writes the file and appends to the log with `origin` |
| `contract.rs` | select contract by task kind, `task_start` (Board obligations), `mark_step` (ticked by ops), `task_done` (reports unfulfilled obligations), `render_agents_block` |
| `lens.rs` | resolve a lens into a view tree of virtual groups |
| `init.rs` | `afwe init` (empty `.afwe/` with default contracts, README, .gitignore), `bootstrap` (propose a blueprint from directory structure) |
| `api.rs` | `call()` dispatcher, `OPS` list, `tool_specs()` (MCP tool catalogue with JSON schemas), `graph` (everything the Studio needs in one call), `search`, node detail |

### `crates/afwe-cli` (binary `afwe`)

* `main.rs` — clap CLI; every subcommand is a thin wrapper around `api::call`; global `-C`, `--origin`, `--json`.
* `render.rs` — human-readable terminal rendering (tree, context, verify, drift, board …).
* `mcp.rs` — MCP server over stdio (JSON-RPC 2.0, protocol `2024-11-05`): `initialize`, `tools/list`,
  `tools/call`, `resources/list`, `resources/read`. Tool names map 1:1 to ops; the default origin is
  `llm:<clientInfo.name>` unless `--origin-name` is given.
* `studio.rs` — `tiny_http` host for the web Studio: `POST /api/call {op, params, origin?}`,
  `GET /api/health`, `GET /api/ops`, static files from the embedded `apps/studio/web-dist`
  (`include_dir`, generated by `build.rs` if missing) or `--dist`.

### `apps/studio` (React 18 + TypeScript + React Flow + zustand, Vite)

`src/api.ts` decides at runtime: inside Tauri → `invoke("call", …)`, otherwise `fetch("/api/call")`. The
rest of the UI never knows which shell it runs in. Components: `TreePanel`, `GraphView` (compact tree
layout, rolled-up relation edges, drag-to-move, connect-to-relate, implementation view, lenses),
`ContextPanel`, `BottomBar`, `DriftDrawer` (proposals · findings · log), `WorkflowView` (node editor),
`BoardView` (tasks, obligations, system items, contracts / AGENTS.md block), `MemoryView` (memory +
guardrails), `SearchPalette` (⌘K).

### `apps/studio/src-tauri` (Tauri v2, separate Cargo workspace)

Commands `call`, `open_project_dialog`, `current_project`, `open_project`; one `Engine` behind a mutex.
Kept out of the root workspace so the engine/CLI build without webkit/WebView2 toolchains.

## Key flows

**`afwe context src/a.ts src/b.ts`** → snapshot (cached) → node chain for each file → memory whose scope
matches (`applies_to` incl. ancestors, `files` globs, `symbols`) → guardrails (+ exceptions) → relations and
constraints touching the chain → code neighbourhood (imports / imported-by / externals / symbols) →
contract for the task kind → markdown + JSON. Marks the `afwe_context` obligation of the open task.

**`afwe verify --changed …`** → refresh snapshot for the changed files → constraint violations on code
edges → guardrail checks in scope → optional drift on the changed files → `ok=false` on any error →
exit code 1. Marks `afwe_verify` when ok.

**`afwe sync`** → full analysis → index → `drift::detect` → bucket by policy → apply confident changes
(`MapFile`, `RemapFile`, `RemapSymbol`, `AddRelation`, `UnmapFile`, …) → proposals for the rest → Board
items for uncertain reconciliations and proposals → `state/*.json`, `log/changes.jsonl`, `sync.json`.

**Rename detection** — a missing mapped file/symbol is matched against new files/symbols by content
fingerprint (exact) or structural path + name similarity; confidence 0.75 – 0.95 depending on the match,
below that it becomes a proposal.

## Design rules

1. **The folder is the product.** Every op writes plain YAML/markdown; nothing lives only in memory or a DB.
2. **Never invent agreement.** Drift is reported with evidence and confidence; policy decides what is applied.
3. **Identity is structural.** Path + symbol + AST path + fingerprint; no line numbers anywhere in `.afwe/`.
4. **One surface.** CLI, MCP, HTTP and Tauri all go through `api::call`; new features are new ops.
5. **AFWE is not a harness.** Contracts state obligations; the engine ticks them off when it observes the
   calls, and reports what is unfulfilled — it never drives the agent.
6. **Language-agnostic by construction.** Adding a language = adding a `LangSpec`; every other layer works
   on the generic code model.

## Testing

`cargo test` runs unit tests in `afwe-core` (mapping resolution, glob scoping, analysis of fixture snippets,
drift heuristics, contract bookkeeping). `examples/demo-project` doubles as an end-to-end fixture:
`afwe sync && afwe verify` there must report exactly one constraint violation (`payments-no-ui`) and one
forbidden pattern (`console.log` in Payments).
